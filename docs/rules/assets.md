# กฎไฟล์ asset, ภาพอ้างอิง และลิขสิทธิ์

> ครอบคลุม: sprite PNG · ไฟล์เสียง · ภาพอ้างอิงสถานที่/วัตถุจริง (ที่เจ้าของแนบมาหรือหาจากเว็บ) · การใช้ AI สร้างภาพ/เสียง · เครดิต

---

## 1. โครงโฟลเดอร์
```
assets-src/                    ไฟล์ต้นฉบับ (ไม่ถูก bundle)
  palette/openlife.gpl         master palette (ต้องตรงกับ src/render/palette.ts)
  sprites/<หมวด>/*.aseprite    ต้นฉบับ sprite
  audio/<หมวด>/*.wav           ต้นฉบับเสียงคุณภาพเต็ม
src/assets/                    ไฟล์ที่เกมใช้จริง (Vite ใส่ hash ให้)
  sprites/<หมวด>/<ชื่อ>.png + <ชื่อ>.json
  audio/{sfx,voice,amb,music}/<ชื่อ>.mp3
  manifest.ts                  รายการ asset ต่อฉาก (preload/lazy)
docs/refs/<หัวข้อ>/            ภาพอ้างอิง (รูปถ่ายจริง) — ไม่อยู่ในเกม
  SOURCES.md                   แหล่งที่มาของภาพอ้างอิงทุกไฟล์
docs/CREDITS.md                เครดิตทุก asset ที่ต้องให้เครดิต
```
- หมวด sprite: `char` (ตัวละคร) · `npc` · `animal` · `vehicle` · `bld` (อาคาร/kit) · `prop` · `tile` (พื้น) · `fx` · `ui` · `portrait`
- สร้างโฟลเดอร์เมื่อมีไฟล์แรก ไม่ต้องสร้างโฟลเดอร์ว่างล่วงหน้า

## 2. สเปกไฟล์
### 2.1 Sprite PNG
- PNG RGBA 32-bit, **ขอบโปร่งใสคม** (ไม่มี anti-alias ไปยังพื้นโปร่งใส), ไม่มี color profile แปลก ๆ
- ขนาดเป็นทวีคูณของ 32 px สำหรับ tile/kit; ตัวละคร 48×64 ต่อเฟรม (ดู [characters.md §2](characters.md))
- สีจาก master palette เท่านั้น — ตรวจด้วยสคริปต์ **[อนาคต: `scripts/check-palette`]**
- sprite sheet: **แถว = ท่า/ทิศ, คอลัมน์ = เฟรม**, ช่องว่างระหว่างเฟรม 0 px
- metadata JSON (รูปแบบ Aseprite export "Array"): `frames[].duration` (ms), `meta.frameTags` (ชื่อท่า เช่น `walk_down`), `meta.slices` สำหรับ `pivot` (จุดยึดที่เท้า) และ `hitbox` ถ้ามี
- ตั้งชื่อ snake_case ภาษาอังกฤษ: `<หมวด>_<สิ่งของ>_<รุ่น>` เช่น `char_adult_body_avg.png`, `bld_shophouse_shutter_a.png`, `prop_spirit_house.png`, `vehicle_tuktuk.png`, `fx_steam.png`
- เลเยอร์ตัวละครที่ต้องเปลี่ยนสี ใช้สีในช่วง "สีกุญแจ" (key ramp) ที่ประกาศใน palette เพื่อ palette swap

### 2.2 ภาพที่วาดด้วยโค้ด
- อยู่ใน `src/render/` แบบ typed; ใช้ primitives ใน `src/render/pixel.ts` และสีจาก palette
- ของที่วาดด้วยโค้ดต้องผลลัพธ์เดิมทุกครั้ง (seeded) และ cache เป็น canvas ครั้งเดียว

### 2.3 เสียง
- เกม: **MP3** 44.1 kHz (รองรับทุกเบราว์เซอร์) — SFX/voice mono 96–128 kbps · ambience/music stereo 128–160 kbps
- ต้นฉบับ: WAV 16/24-bit เก็บใน `assets-src/audio/`
- ambience/music ต้องวน loop ได้ไม่มีรอยต่อ (ตัดที่ zero-crossing, crossfade ภายในไฟล์)
- ตัดความเงียบหัว-ท้ายของ SFX; normalize ตามระดับใน [audio.md §8](audio.md)
- ขนาด: SFX ≤ 100 KB · ambience loop ≤ 1 MB · เพลง ≤ 3 MB ต่อเพลง

### 2.4 งบขนาดรวม
| ส่วน | งบ |
|---|---|
| ก่อนเห็นเมนูหลัก (JS+CSS+asset) | ≤ 3 MB |
| ต่อฉาก (lazy load) | ≤ 2 MB |
| texture ใน memory บนมือถือ | ≤ ~150 MB |
- เกินงบ → แจ้งเจ้าของก่อน

## 3. การโหลดและ fallback
- ทุกฉากมีรายการ asset ใน `manifest.ts`; preload ของฉากถัดไปที่น่าจะไปขณะผู้เล่นอยู่ฉากปัจจุบัน
- sprite โหลดไม่ได้ → ใช้ภาพที่วาดด้วยโค้ด/กรอบสำรอง + `console.warn` ครั้งเดียว (**ห้าม error** เพราะ DoD ต้องไม่มี console error)
- เสียงโหลดไม่ได้ → เงียบหรือใช้เสียงสังเคราะห์
- ห้ามโหลด asset จากโดเมนภายนอกตอนเล่น (ยกเว้นฟอนต์ Google Fonts ที่ใช้อยู่)

## 4. ลิขสิทธิ์และแหล่งที่มา (บังคับ)
- **ทุก asset ต้องบันทึกที่มา**: สร้างเอง / เจ้าของให้มา / แหล่งภายนอก (URL + license + ผู้สร้าง + วันที่)
- License ที่รับได้: **CC0** (ดีที่สุด) · CC-BY (ต้องใส่ใน `docs/CREDITS.md`) · license ที่อนุญาตใช้ในเกมเชิงพาณิชย์ชัดเจน
- **ห้าม:** CC-BY-NC / ND (เว้นเจ้าของอนุมัติ), ไฟล์ที่ไม่รู้ที่มา, ripped asset จากเกม/หนัง/ทีวี/เพลงค้า, เสียง/ภาพที่จำได้ว่าเป็นแบรนด์จริง
- asset ที่ AI สร้าง: บันทึกว่าเป็น AI + เครื่องมือที่ใช้ใน SOURCES/CREDITS; ห้ามสั่งเลียนแบบสไตล์ศิลปินที่ยังมีชีวิตหรือเกมเฉพาะเจาะจง; ภาพ AI ใช้เป็น **concept/อ้างอิง** แล้วต้องทำความสะอาดเป็นพิกเซลอาร์ตตาม palette ก่อนใช้จริง
- ไฟล์ที่เจ้าของแนบมา: ถือว่าเจ้าของรับผิดชอบสิทธิ์ แต่ต้องบันทึก "เจ้าของให้มา + วันที่ + ที่มาที่เจ้าของบอก" และถามถ้าไม่แน่ใจว่าใช้ในเกมได้หรือแค่ใช้อ้างอิง

## 5. ภาพอ้างอิงสถานที่/วัตถุจริง
เจ้าของอาจแนบรูปถ่ายสถานที่จริง วัตถุจริง หรือเสียงจริง เพื่อให้งานตรงความจริง
### 5.1 ขั้นตอนเมื่อได้รับภาพอ้างอิง
1. บันทึกไฟล์ลง `docs/refs/<หัวข้อ>/<yyyymmdd>-<slug>.<ext>` (เช่น `docs/refs/shophouse/20261110-yaowarat-row.jpg`)
2. เพิ่มรายการใน `docs/refs/<หัวข้อ>/SOURCES.md`: ที่มา · ผู้ให้ · วันที่ · สิทธิ์ (ใช้อ้างอิงเท่านั้น/ใช้ในเกมได้) · สิ่งที่ต้องเรียนรู้จากภาพ
3. เขียน **visual brief** ลงใน research card ที่เกี่ยวข้อง: รูปทรง สัดส่วน วัสดุ สีหลัก (hex) รายละเอียดที่ทำให้ "เป็นที่นี่" สิ่งที่ห้ามพลาด
4. วาดพิกเซลอาร์ตจาก brief + ภาพ ตามกฎ [art.md](art.md)

### 5.2 กฎการใช้ภาพอ้างอิง
- ใช้เพื่อเรียน **รูปทรง สัดส่วน วัสดุ สี และรายละเอียดเฉพาะถิ่น** — **ห้าม trace หรือแปลงรูปถ่ายเป็นพิกเซลอัตโนมัติ** แล้วใช้ตรง ๆ
- ห้ามคัดลอก ตัวอักษร โลโก้ ป้ายร้านจริง หน้าคนที่จำได้ หรือป้ายทะเบียน
- รูปถ่ายอ้างอิงไม่ถูก bundle ในเกม (อยู่ใน `docs/` เท่านั้น)
- ภาพจากเว็บที่ไม่มี license ใช้ได้แค่ "ดูอ้างอิง" และต้องบันทึก URL — ห้ามคัดลอกลงโปรเจ็คถ้า license ไม่อนุญาต (บันทึกแค่ลิงก์)
- เสียงจริงที่เจ้าของอัดมา: ตัดต่อ/ทำความสะอาดได้ ต้องไม่มีเสียงพูดที่ระบุตัวบุคคลได้
