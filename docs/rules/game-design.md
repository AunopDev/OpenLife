# กฎการออกแบบเกม (Game Design & Strategy)

> ตัวเลขปัจจุบันอยู่ใน [`docs/GDD.md`](../GDD.md) — ไฟล์นี้คือ **หลักการ** ที่ตัวเลขและระบบทุกอย่างต้องเคารพ
> เปลี่ยน mechanic แล้วต้องอัปเดต GDD เสมอ

## 1. เสาหลัก (Design Pillars) — ห้ามละเมิด
1. **ทุกการกระทำมีราคา** — ไม่มีตัวเลือกที่ดีทุกด้าน ผู้เล่นต้องเสียบางอย่างเสมอ (เวลา เงิน สุขภาพ ความสัมพันธ์ โอกาส)
2. **เงินไม่ใช่คำตอบเดียว** — ตอนจบวัดจากความฝัน ครอบครัว สุขภาพ และความหมาย ไม่ใช่ยอดเงิน
3. **บริบทไทยจริง** — หนี้บัตร เครดิตบูโร กยศ. ย้ายถิ่น ระบบอาวุโส ซองงาน เงินเดือนออกวันที่ 25
4. **ความตายคือบทส่งท้าย** — ไม่ใช่ game over แต่เป็นการสรุปชีวิตที่มีความหมาย

## 2. ปรัชญาความยาก — "สนุกก่อน สมจริงแต่ยุติธรรม"
- **สนุกก่อน:** ทุกช่วงเวลาต้องมีอะไรให้ตัดสินใจหรือรู้สึก ถ้าระบบไหนสมจริงแต่น่าเบื่อ ให้ย่อหรือทำอัตโนมัติ
- **ยุติธรรม:** ผู้เล่นแพ้ได้เพราะ**การตัดสินใจ** ไม่ใช่เพราะ**ดวงครั้งเดียว**
  - ห้ามมี event สุ่มครั้งเดียวที่ทำลายชีวิต (เสียเงิน >30% ของทรัพย์สินสุทธิ หรือสุขภาพ −40) ถ้าผู้เล่นไม่ได้เลือกเสี่ยงเอง
  - ความเสี่ยงร้ายแรงต้องมี**สัญญาณเตือนล่วงหน้า** (เช่น ตรวจสุขภาพเตือน → ป่วยหนัก, ทวงหนี้ → ฟ้อง)
  - ทุกวิกฤตต้องมีทางรอดอย่างน้อย 1 ทาง (แม้จะเจ็บ)
- **ภูมิหลังเริ่มต้นต่างกันได้** (ครอบครัวยากจนเริ่มยากกว่า) แต่ต้องมีเส้นทางไปสู่ตอนจบที่ดี และแต่ละภูมิหลังต้องมีจุดแข็งของตัวเอง
- **ทางเลว = โหดสมจริง** — ดู §5
- ความยากต้องรู้สึก "สมเหตุสมผล" — ผู้เล่นอ่านแล้วเข้าใจว่าทำไมถึงเกิดผลนั้น

## 3. ระบบสถานะ (Stats)
- stat หลัก 8 ตัว: `health heart energy money kpi credit smarts social` (ช่วง 0–100 ยกเว้น `money` ≥ 0)
- ความสัมพันธ์ `life.rel`: `family friend love boss` (0–100)
- กฎ:
  - ทุก stat ต้อง **มีผลต่อสิ่งอื่น** อย่างน้อย 2 อย่าง (ไม่มี stat ประดับ)
  - ห้ามให้ stat ใดถึง 100 ง่ายเกินไปจนไม่มีความหมาย — ต้องมี decay หรือ diminishing returns
  - เงินห้ามติดลบ: ถ้าจ่ายไม่พอ ให้ทบเป็นหนี้ (ops `debt`) ไม่ใช่ปล่อย money < 0
  - stat ใหม่ต้องเพิ่มใน `src/core/state.ts` (type) + default ใน `loadGame()` + GDD + invariant audit
- แสดงผลกระทบแก่ผู้เล่นเป็น**แนวโน้ม** (ขึ้น/ลง เล็ก/กลาง/ใหญ่) ยกเว้นเงินที่เป็นราคาที่ตัวละครรู้ล่วงหน้า ซึ่งแสดงตัวเลขได้

## 4. การเลือก (Choice design)
- event มีตัวเลือก **2–4 ข้อ** (3 ข้อดีที่สุด)
- ไม่มีตัวเลือกที่ดีกว่าข้ออื่นทุกด้าน (dominant choice) — ถ้ามี ให้เพิ่มราคา
- ตัวเลือกควรต่างกันที่ **คุณค่า** (ครอบครัว vs งาน, ปลอดภัย vs โอกาส) ไม่ใช่แค่ตัวเลข
- ตัวเลือกที่ต้องใช้ทรัพยากร (เงิน/ความสัมพันธ์) ต้องตรวจเงื่อนไข ไม่ให้เลือกแล้วเกิดสถานะผิด
- อย่างน้อย 1 ตัวเลือกต้องทำได้เสมอ (ไม่ติดเงื่อนไข)
- ผลระยะยาวใช้ flag แล้วตามมาใน event อนาคต (5–20 ปีต่อมาได้) — นี่คือหัวใจของ "ชีวิต"

## 5. ระบบศีลธรรมและผลกรรม (ทางเลว = โหดสมจริง)
เจ้าของกำหนดไว้ว่า: **ถ้าผู้เล่นเลือกเป็นคนเลวเกินไป เกมจะเปลี่ยนเป็นโหมดโหดสมจริง**

### 5.1 ระดับความผิด
| ระดับ | ตัวอย่าง | ผลที่ตามมา |
|---|---|---|
| เทา | โกหกเล็ก ๆ, อู้งาน, ไม่ใส่ซอง | ผลเล็ก บางครั้งรอด สะสมเป็นชื่อเสียง |
| ทำร้ายคนใกล้ชิด | นอกใจ, ทิ้งพ่อแม่ป่วย, เบี้ยวหนี้เพื่อน, โกงหุ้นส่วน | ความสัมพันธ์พังบางส่วนแบบถาวร, ถูกจดจำ (flag), event ตามมาภายหลัง |
| ผิดกฎหมายร้ายแรง | ยักยอก, รับสินบน, ค้ายา, ฉ้อโกงลูกค้า, ทำร้ายร่างกาย | ได้ผลระยะสั้นมาก แต่ความเสี่ยงถูกจับสะสม → คดี/ติดคุก/ตอนจบ "ติดคดี" |

### 5.2 กฎของผลกรรม
- **สมส่วน:** ผลหนักตามความผิด ไม่ลงโทษเกินจริงเพื่อสั่งสอน
- **ล่าช้าได้แต่ไม่ลืม:** ผลอาจมาในอีกหลายปีผ่าน flag (เช่น `embezzled` → อายุ 45 ถูกตรวจสอบบัญชี)
- **ยิ่งทำซ้ำยิ่งเสี่ยง (escalation):** ความผิดซ้ำเพิ่มโอกาสถูกจับแบบทวีคูณ ไม่ใช่เท่าเดิมทุกครั้ง
- **เงินแก้ได้ไม่หมด:** เงินช่วยลดโทษทางกฎหมายได้บางส่วน แต่ซื้อความสัมพันธ์/ความไว้ใจคืนไม่ได้
- **มีทางกลับตัว แต่มีราคา:** สารภาพ ชดใช้ ขอโทษ — เสียเงิน/เวลา/ศักดิ์ศรี แต่เปิดทางสู่ตอนจบที่ดีขึ้น
- **แสดง ไม่สั่งสอน:** ห้ามมีข้อความเทศนา ให้ผลที่ตามมาเล่าเรื่องเอง
- ตอนจบต้องสะท้อนวิธีใช้ชีวิต: รวยจากการโกง ≠ ตอนจบ "เกษียณอย่างสงบ"

### 5.3 การนำไปใช้ในโค้ด
- ตอนนี้ใช้ `life.flags` (เช่น `crime`) + ความสัมพันธ์
- **[อนาคต]** ค่า `life.karma` (−100..100) และ `life.heat` (ความเสี่ยงถูกจับ 0–100) — ถ้าจะเพิ่ม ต้องทำตาม §3 (state.ts + save default + GDD + audit) และถามเจ้าของก่อน
- event ทางเลวต้องตั้ง flag ที่มีความหมาย และต้องมี event ผลตามมาอย่างน้อย 1 อัน (ห้ามมีความผิดที่ไม่มีผล)

## 6. เวลาและจังหวะ
- โครง 10 บท (0→6→12→18→22→27→35→45→55→60→ตาย) และ hybrid time (+1/+3/+6/+12 เดือน) — รายละเอียดใน GDD §2
- ก้าวสั้นต้องได้ content/กิจกรรมมากกว่า ก้าวยาวต้องเร็วกว่า — **ห้ามมีความเร็วไหนถูกลงโทษเชิงกลไก** (เช่น ความเสี่ยงตายต่อปีต้องเท่ากันทุกความเร็ว)
- ทุกตัวเลขต่อเดือนต้องคูณตามจำนวนเดือนที่เดิน
- 1 ช่วงเวลาควรใช้เวลาเล่นจริง 1–3 นาที; ชีวิตเต็ม 4–6 ชั่วโมง

## 7. กิจกรรม
- กิจกรรมต่อช่วงตามงบ 3/5/7/9 และทำซ้ำได้ผล 100/50/25/0%
- ค่าลบ/ค่าใช้จ่ายไม่ลดตาม diminishing returns (กันการปั๊มผลบวก)
- กิจกรรมใหม่ต้องมีทั้งผลบวกและราคา และต้องไม่ดีกว่ากิจกรรมเดิมทุกด้าน
- กิจกรรมเฉพาะเขต/ย่านต้องอิง research ของพื้นที่นั้น

## 8. ความหลากหลายและการเล่นซ้ำ
- ภูมิหลัง 4 แบบ × ความฝัน 6 แบบ × จังหวัด/เขต/ย่าน ต้องให้ประสบการณ์ต่างกันจริง (event เฉพาะ, ค่าใช้จ่าย, โอกาส)
- ลด event ซ้ำ: `recentEvents` + cross-run memory (`src/core/picker.ts`) — event ใหม่ต้องเข้าระบบนี้
- ทุกความฝันต้องเป็นไปได้ในทุกภูมิหลัง (ยากง่ายต่างกันได้)

## 9. ตอนจบ
- `endingFor()` มี 8 แบบ — ตอนจบใหม่ต้องมีเงื่อนไขที่ไม่ทับกับแบบเดิม และสะท้อนวิธีใช้ชีวิต
- หน้าสรุปต้องเล่าเรื่อง (ความฝัน ครอบครัว จุดเปลี่ยนสำคัญจาก `life.log`/milestones) ไม่ใช่แค่ตัวเลข

## 10. เป้าหมาย balance (เป้าออกแบบ — ตรวจด้วย simulation)
> ค่าเหล่านี้เป็น **เป้าออกแบบ** ไม่ใช่ข้อเท็จจริง ต้องยืนยันด้วยการจำลองหลายรอบ (ดู [economy.md §6](economy.md))

| ผู้เล่นแบบ | เป้าตอนจบ |
|---|---|
| สมดุล (ทำงาน ดูแลสุขภาพ จ่ายหนี้) | ~60–70% ได้ตอนจบกลาง–ดี, ทรัพย์สินตอนเกษียณ "พอใช้" ไม่ใช่หลายสิบล้าน |
| ทำงานหนักอย่างเดียว | เงินดีแต่สุขภาพ/ครอบครัวแย่ → ตอนจบ "รวยแต่ตัวคนเดียว"/"หมดไฟ" บ่อย |
| ใช้จ่ายเกินตัว | หนี้สะสม เครดิตพัง มีโอกาสฟื้นถ้าปรับตัวทัน |
| ทางเลว | ได้เงินเร็ว แต่ส่วนใหญ่จบที่คดี/ความสัมพันธ์พัง |
