# กฎเศรษฐกิจและตัวเลขเงิน (Economy)

> ตัวเลขทุกตัวที่ผู้เล่นเห็นต้องตอบได้ว่า "มาจากไหน"
> ข้อมูลหลัก: `src/data/finance.json`, `debts.json`, `career.json`, `provinces.json`, `geo.json` (rent/salary ของย่าน) · สูตรอยู่ใน `src/game.ts` (กำลังทยอยแยกออก)

## 1. แหล่งที่มาของตัวเลข
- ทุกตัวเลขที่อิงโลกจริง (เงินเดือน ค่าเช่า ค่าแรงขั้นต่ำ ราคา ภาษี ดอกเบี้ย ประกันสังคม) ต้องมี **แหล่ง + ปีของข้อมูล** ใน research card
- แหล่งที่ใช้ได้ก่อน: NSO, ธปท., กรมสรรพากร, สำนักงานประกันสังคม, กระทรวงแรงงาน, รายงานเงินเดือนของบริษัทจัดหางาน
- ตัวเลขที่ "ย่อเพื่อเกม" ต้องเขียนกำกับใน GDD ว่าย่อจากอะไร เช่น
  - ภาษีในเกมใช้ขั้นบันไดแบบย่อ 5/8/12/17% — **ไม่ใช่อัตราจริง** (อัตราจริงมีหลายขั้นและมีค่าลดหย่อน) TODO(research): ทำ card ภาษีเงินได้บุคคลธรรมดา
  - ประกันสังคม 5% เพดาน 750 — TODO(research): ตรวจเพดานค่าจ้างที่ใช้ในปีปัจจุบัน
  - ขั้นต่ำบัตรเครดิตในเกมเป็นจำนวนคงที่ — TODO(research): อัตราขั้นต่ำที่ ธปท. กำหนด

## 2. ปีในเกม
- ตัวละครเกิด พ.ศ. 2547 → อายุ 22 = พ.ศ. 2569 (ปีที่เกมอ้างอิงเป็นฐาน)
- ราคาฐานใช้ค่าของปีฐาน แล้วปรับด้วย `costInflation()` (+2%/ปี หลังอายุ 22) กับค่าที่อยู่ เดินทาง ครอบครัว
- **ห้าม hardcode ราคาที่ไม่ผ่านเงินเฟ้อ** ในช่วงอายุ >22 ยกเว้นเป็นค่าคงที่ตามสัญญา (เช่น ค่างวดผ่อน)

## 3. รายรับ–รายจ่าย
- เงินเดือน/บิล/ดอกเบี้ย/ค่าครองชีพ คิดเป็น "ต่อเดือน" แล้วคูณจำนวนเดือนที่เดินเสมอ
- ทุกรายการที่หักต้องแสดงในสลิป (`showPayslip`) หรือหน้าการเงิน — **ไม่มีเงินหายแบบมองไม่เห็น**
- ค่าใช้จ่ายต่อเนื่องใหม่ต้องเข้า `fixedPerMonth()` หรือ helper ที่เกี่ยวข้อง และแสดงในหน้าการเงิน
- ค่าครองชีพต่างตามจังหวัด/ย่าน (`geoFinance`) — ย่านใหม่ต้องมี rent/salary ที่อ้างอิงได้

## 4. หนี้และเครดิต
- หนี้ต้องจ่ายเอง (ไม่หักอัตโนมัติ เว้นแต่ผู้เล่นเปิด auto) — ค้างจ่ายแล้วมีผลเป็นขั้น: เตือน → เจ้าหนี้ตาม → ฟ้อง → ล้มละลาย (มี grace)
- เงินไม่พอจ่าย → ทบเข้าบัตรเครดิต + แจ้งเตือน (ห้ามให้ money ติดลบ)
- เครดิต 0–100 ส่งผลต่อการกู้/ซื้อบ้าน/รถ — เงื่อนไขอนุมัติต้องสอดคล้องกันทุกที่
- หนี้ประเภทใหม่: เพิ่มใน `debts.json` + type `DebtKey` ใน `src/core/state.ts` + default ใน `loadGame()` + หน้า F

## 5. Money sink และเงินส่วนเกิน
- เกมต้องมีที่ใช้เงินที่มีความหมาย (บ้าน รถ ห้องเช่า ทริป บริจาค ธุรกิจ ครอบครัว) — ตอนนี้ยังไม่พอ (ดู `docs/BALANCE.md`)
- money sink ใหม่ต้องให้อะไรที่ไม่ใช่แค่ตัวเลข (ความสุข ความสัมพันธ์ prestige ตอนจบ) และมีค่าดูแลต่อเนื่องถ้าเป็นทรัพย์สิน
- ห้ามทำ sink ที่บังคับจ่ายโดยไม่มีทางเลือก (ภาษีใหม่/ค่าปรับลอย ๆ) เว้นแต่อิงระบบจริง

## 6. กระบวนการปรับ balance
1. ระบุปัญหาด้วยตัวเลข (จาก simulation หรือการเล่นจริง)
2. เปลี่ยนทีละตัวแปร และบันทึกเหตุผล
3. รันจำลอง **อย่างน้อย 5 รอบต่อกลยุทธ์** (balanced / workaholic / spender / ทางเลว) ทุกความเร็ว (+1/+3/+6/+12)
4. รายงานค่าเฉลี่ยและช่วงต่ำ–สูงใน `docs/BALANCE.md`
5. เทียบกับเป้าใน [game-design.md §10](game-design.md)
- **[อนาคต]** ย้ายตรรกะเงิน/เวลาไปโมดูลที่ไม่แตะ DOM แล้วรันจำลองใน Node ได้ (ดู [code.md §2](code.md))
