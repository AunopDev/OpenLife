# กฎ UX/UI — Responsive (ทุกอุปกรณ์สำคัญเท่ากัน)

> เจ้าของกำหนด: **Responsive** — มือถือ แท็บเล็ต และเดสก์ท็อป ต้องเล่นได้ครบและดีเท่ากัน ไม่มีอุปกรณ์ไหนเป็น "รอง"
> หลักคิด: ไม่ใช่แค่ย่อ/ขยายหน้าจอเดียว แต่**จัดเลย์เอาต์และวิธีควบคุมให้เหมาะกับแต่ละอุปกรณ์** โดยใช้เนื้อหาและระบบชุดเดียวกัน

## 1. หลักใหญ่
1. **ทุกอุปกรณ์เล่นได้ครบทุกฟีเจอร์** — แตะ (มือถือ/แท็บเล็ต) และเมาส์ + คีย์บอร์ด (เดสก์ท็อป) ต้องทำได้ทุกอย่างเท่ากัน
2. **ใช้จุดแข็งของแต่ละอุปกรณ์** — มือถือ: แตะด้วยนิ้วเดียว ปุ่มในระยะนิ้วโป้ง · เดสก์ท็อป: ใช้พื้นที่จอกว้าง (แผงข้าง/ข้อมูลมากขึ้น) hover แสดงรายละเอียดเสริม คีย์ลัด · แท็บเล็ต: ได้ทั้งสองแบบ
3. **หนึ่งหน้าจอ หนึ่งการตัดสินใจ** — modal หนึ่งอันถามเรื่องเดียว
4. **ไม่มีการกด/แตะที่เสียเปล่า** — ทุกการกระทำต้องมีผลหรือตอบสนองทันที
5. **อ่านเร็ว ตัวเลขชัด** — ผู้เล่นต้องรู้สถานะหลักโดยไม่ต้องเปิดเมนู ในทุกขนาดจอ
6. **โลกเกมเป็นตัวควบคุม** — แตะ/คลิกพื้นเพื่อเดิน แตะ/คลิกอาคารเพื่อโต้ตอบ **ห้ามมี D-pad หรือแผงปุ่มถาวรบนจอ** (คีย์บอร์ด WASD เป็นทางเลือกบนเดสก์ท็อป)
7. **HUD คือเมนู** — นาฬิกา = เดินเวลา, ช่องเงิน = การเงิน/หนี้, การ์ดชื่อ = ภาพรวมชีวิต, `?` = คู่มือ/ทัวร์
8. **ไม่เปลืองพื้นที่จอ** — ทุกขนาดจอต้องใช้พื้นที่อย่างคุ้มค่า ห้ามมีแถบว่างใหญ่ (เช่น โลกเกมเล็กกลางจอแล้วเหลือพื้นดำครึ่งจอ)

## 2. ขนาดจอที่ต้องทดสอบทุกครั้ง (สำคัญเท่ากันทุกแถว)
| อุปกรณ์ | ขนาด (CSS px) | สิ่งที่ต้องได้ |
|---|---|---|
| มือถือ portrait | 375×812 (และ 360×740) | เล่นได้ครบ event/เมนูอ่านสบาย ปุ่มในระยะนิ้วโป้ง โลกเกมใช้พื้นที่คุ้ม |
| มือถือ landscape | 812×375 | แผนที่ใหญ่ HUD บังโลกไม่เกิน ~25% |
| แท็บเล็ต | 768×1024 (และแนวนอน 1024×768) | ใช้พื้นที่มากกว่ามือถือ ไม่ใช่มือถือขยาย |
| เดสก์ท็อป | 1440×900 (และ 1920×1080) | ใช้จอกว้างให้คุ้ม ข้อความไม่ยืดยาวเกิน (บรรทัดละ ~60–80 ตัวอักษร) รองรับเมาส์/คีย์บอร์ดเต็มที่ |
- e2e ทดสอบอัตโนมัติ 4 ขนาด (mobile-portrait, mobile-landscape, tablet, desktop) — ขนาดอื่นตรวจด้วยตาเมื่อแก้ UI
- breakpoint ปัจจุบัน: ≤1200 (แท็บเล็ต), ≤900 (มือถือ), `max-height:500px` (landscape เตี้ย), `orientation:portrait`
- เลย์เอาต์ต้องลื่นระหว่าง breakpoint (ลากขนาดหน้าต่างแล้วไม่มีช่วงที่พัง/ซ้อนกัน)
- `#world` จัดกลางจอ, HUD (`#stage`) แยกออกจากโลก และรองรับ `env(safe-area-inset-*)` เสมอ

## 3. การควบคุมและเลย์เอาต์
- พื้นที่กด/แตะขั้นต่ำ **44×44 CSS px** ทุกอุปกรณ์ และห่างกันอย่างน้อย 8px
- ตำแหน่งปุ่มหลักสม่ำเสมอทุก modal: มือถือ = ครึ่งล่างของจอ (โซนนิ้วโป้ง) · เดสก์ท็อป = มุมขวาล่างของ modal
- modal: มือถือ portrait เป็นแผ่นล่าง (bottom sheet) เต็มความกว้าง · แท็บเล็ต/เดสก์ท็อป เป็นกล่องกลางจอ ความกว้างจำกัด (~520–720px)
- **hover ใช้ได้เป็นข้อมูลเสริมบนเดสก์ท็อปเท่านั้น** — ข้อมูลเดียวกันต้องเปิดด้วยการแตะได้บนอุปกรณ์สัมผัส (ตรวจด้วย `@media (hover: hover)`)
- คีย์ลัดแสดงในคู่มือและ tooltip บนเดสก์ท็อปได้ แต่ห้ามเป็นวิธีเดียวในการทำสิ่งใด
- gesture ที่ใช้ได้: แตะ, แตะค้าง (ถ้ามีคำอธิบาย), pinch/ล้อเมาส์ ซูมแผนที่ — ห้าม gesture ลับที่ไม่มีทางรู้
- การซูม/เลื่อนของเบราว์เซอร์ต้องไม่ชนกับ gesture ของเกม

## 4. ตัวอักษรภาษาไทย
- ฟอนต์: หัวข้อ/HUD **Chakra Petch**, เนื้อหา **Noto Sans Thai**, ตัวเลขใช้ `font-variant-numeric: tabular-nums`
- ขนาดขั้นต่ำ: เนื้อหา **16px** (เดสก์ท็อปใหญ่ขึ้นได้), ป้าย/คำอธิบายรอง 13px, ตัวเลข HUD 14px — ใช้หน่วยที่สเกลได้ (rem/clamp) ไม่ fix px ทั้งหมด
- `line-height` ของข้อความไทย ≥ 1.5 (สระบน/ล่าง/วรรณยุกต์ต้องไม่ชนกัน)
- ห้ามใส่ `letter-spacing` และห้ามบังคับตัวพิมพ์ใหญ่กับข้อความไทย
- ตัดบรรทัด: อย่าตัดกลางคำ — ใช้ `word-break: keep-all` ไม่ได้กับไทย ให้ใช้ `overflow-wrap: anywhere` เฉพาะที่จำเป็น และควบคุมความยาวข้อความแทน
- ข้อความยาวเกิน → ย่อเนื้อหา ไม่ใช่ย่อฟอนต์

## 5. สีและการมองเห็น
- พาเลตต์ UI กรมท่า (GDD §12.1): Navy 900/700/500 + เหลือง/ส้ม/ชมพู/เขียว/แดง/ฟ้า
- คอนทราสต์ข้อความ ≥ 4.5:1 (ข้อความใหญ่ ≥ 3:1)
- **ห้ามใช้สีอย่างเดียวสื่อความหมาย** — ขึ้น/ลงต้องมีลูกศรหรือเครื่องหมาย +/− ด้วย (คนตาบอดสีแดง-เขียว)
- สถานะอันตราย (เงินใกล้หมด สุขภาพต่ำ หนี้ค้าง) ต้องมีทั้งสี ไอคอน และข้อความ

## 6. Feedback และการแจ้งเตือน
- ตอบสนองภายใน 100ms (ปุ่มกด เสียง หรือ animation)
- toast สำหรับข้อมูลรอง (≤ 1 บรรทัด, ใช้ `aria-live`) — **ห้ามใช้ toast กับข่าวสำคัญ** (ความตาย เลย์ออฟ ฟ้องร้อง) ให้ใช้ modal
- ผลของตัวเลือกแสดงเป็นแนวโน้ม (ดู [game-design.md §3](game-design.md))
- การกระทำที่ย้อนไม่ได้ (เขียนทับเซฟ จ่ายเงินก้อนใหญ่ ขายทรัพย์ ย้ายจังหวัด) ต้องมีหน้ายืนยันที่บอกผลชัด
- ระหว่างโหลด/สร้างแผนที่ ต้องมีสัญญาณว่ากำลังทำงาน

## 7. การสอนผู้เล่น (Onboarding)
- สอนในเนื้อเรื่อง (3 เทิร์นแรกของบท 5) + coach tour 4 สเต็ปที่ข้ามได้ + คู่มือใน `?`
- ฟีเจอร์ใหม่ที่ผู้เล่นต้องรู้ → เพิ่มในคู่มือ (`openHelp`) และพิจารณาเพิ่มในทัวร์
- ห้ามโชว์คีย์ลัดเป็นข้อมูลหลักบนมือถือ

## 8. Accessibility
- modal ใช้ `role="dialog"`, จัด focus เข้า modal และคืน focus เมื่อปิด
- `:focus-visible` ชัดเจน; ใช้งานด้วยคีย์บอร์ดได้บนเดสก์ท็อป
- เคารพ `prefers-reduced-motion` (ลด animation/shake/parallax)
- เสียงปิดได้และจำค่า (`openlife.sound`); ห้ามมีข้อมูลที่สื่อด้วยเสียงอย่างเดียว

## 9. ประสิทธิภาพที่ผู้เล่นรู้สึกได้
- โหลดครั้งแรกบนมือถือ 4G ระดับกลาง: เป้า < 3 วินาทีจนเห็นเมนู
- เป้า 60fps (ขั้นต่ำ 30fps บนเครื่องรุ่นเก่า); หยุด loop เมื่อแท็บถูกซ่อนหรือหยุดเกม
- `updateHud()` ถูก throttle (≤ ทุก 200ms) — อย่าอัปเดต DOM ทุกเฟรม

## 10. ข้อความบนหน้าจอ
- ภาษาไทยทั้งหมด กระชับ ปุ่มขึ้นต้นด้วยกริยา ("จ่ายบิล", "เดินเวลา +3 เดือน")
- ใช้คำเดียวกันทั้งเกมสำหรับสิ่งเดียวกัน (เช่น "ใจ" ไม่สลับกับ "ความสุข")
- เงิน/วันที่ตาม [economy.md §7](economy.md)

## 11. Checklist งาน UI
- [ ] ทดสอบครบทุกขนาดจอใน §2 — ทุกอุปกรณ์เล่นได้ครบและดูดีเท่ากัน
- [ ] เลย์เอาต์ปรับตามอุปกรณ์ (ไม่ใช่แค่ย่อขยาย) และไม่มีพื้นที่ว่างเปลืองจอ
- [ ] ทำได้ทั้งด้วยการแตะและเมาส์/คีย์บอร์ด, เป้ากด ≥ 44px, hover เป็นข้อมูลเสริมเท่านั้น
- [ ] ข้อความไทยไม่ชน ไม่ถูกตัด ไม่ล้นกรอบ
- [ ] คอนทราสต์ผ่าน และไม่ใช้สีอย่างเดียว
- [ ] reduced-motion และ safe-area ทำงาน
- [ ] คู่มือ/ทัวร์อัปเดต (ถ้าเป็นฟีเจอร์ใหม่)
