# กฎการสร้างแผนที่ (จังหวัด → เขต/อำเภอ → ย่าน)

> ทุกแผนที่ต้องมี research ก่อน (ดู [research.md](research.md)) และผ่าน audit + test
> งานภาพของแผนที่ดู [art.md](art.md) · การตรวจดู [quality.md](quality.md)

## 0. หลักกัน "มั่วโดยไม่มีอะไรเตือน" (บังคับ)
1. **ข้อมูลเป็นแหล่งความจริงเดียว** — หน้าตาและลักษณะของแผนที่ทุกพื้นที่กำหนดใน `src/data/geo.json` (ช่อง `map`) เท่านั้น
2. **ห้ามเช็กชื่อ/id ของจังหวัดหรือเขตในโค้ด** (เช่น `if (provinceId === 'chiang-mai')`) — ถ้าต้องการพฤติกรรมใหม่ ให้เพิ่มช่องใน `map` + type ใน `src/world/geo.ts` + test ใน `tests/unit/geo-config.test.ts`
3. **ห้ามมีค่า fallback เงียบ ๆ** — ทุกจังหวัด/เขตต้องกรอก `map` ครบ; test จะล้มถ้าขาด
4. **ทุกพื้นที่ต้องมี research card ที่ประกาศ `geo:`** — ของเก่าที่ยังไม่มีอยู่ในรายการหนี้งาน (ห้ามเพิ่มรายการ ทำได้แค่ลบเมื่อทำเสร็จ)
5. **ค่าที่เลือกต้องมีเหตุผลจาก research** — เขียนเหตุผลไว้ใน card หัวข้อ 3 (ภูมิศาสตร์) และ 8 (สิ่งที่แต่งเพิ่ม)
6. **ดูภาพทุกพื้นที่ที่เพิ่มด้วยตา** — เทียบกับ visual brief ใน card ([quality.md §4](quality.md))

## 1. ลำดับชั้นภูมิศาสตร์
- **จังหวัด → เขต/อำเภอ → ย่าน** เก็บใน `src/data/geo.json` ใช้ผ่าน `src/world/geo.ts`
- คำที่ใช้: "เขต" เฉพาะกรุงเทพฯ, "อำเภอ" จังหวัดอื่น (`province.unit`), "ย่าน" เป็นชื่อเชิงสังคม/เศรษฐกิจ ไม่ใช่หน่วยราชการ
- id ทั้งหมดเป็นภาษาอังกฤษตัวเล็ก + ขีดกลาง ตามการถอดเสียงทั่วไป (เช่น `mueang-chiang-mai`) และห้ามซ้ำ
- ตอนนี้มี 8 จังหวัด: กรุงเทพฯ นนทบุรี ปทุมธานี สมุทรปราการ เชียงใหม่ ขอนแก่น ชลบุรี สงขลา
- รายชื่อจังหวัดในเมนู (`src/data/provinces.json`) **ต้องตรงกับ `geo.json` ทุกชื่อและลำดับ** (test + `geoAudit` ตรวจ)

### โครงข้อมูลใน `geo.json`
```
province: {
  id, name, unit: 'เขต'|'อำเภอ', region: 'กลาง'|'เหนือ'|'อีสาน'|'ตะวันออก'|'ใต้', salary, rent,
  map: { palette, region, inlandWater, roadLayout },
  districts[]
}
district: {
  id, name, vibe,
  map: { archetype, coastal, wat, landmark: { name, roof, sign }, roof?, houseRoof? },
  neighborhoods[]
}
neighborhood: { id, name, vibe, zone, rent, salary, tags[], mapId? }
```

### ความหมายของค่าตั้งแผนที่
| ช่อง | ค่า | ความหมาย / เลือกอย่างไร |
|---|---|---|
| `province.map.palette` | `bangkok` `central` `north` `isan` `east` `south` | ชุดสีพื้น หญ้า ทราย ทะเล หลังคา ของภาค — ต้องเท่ากับ `map.region` |
| `province.map.region` | เดียวกับ palette | ต้องสอดคล้องกับ `region` ภาษาไทย (กลาง → `bangkok`/`central`, เหนือ → `north`, อีสาน → `isan`, ตะวันออก → `east`, ใต้ → `south`) |
| `province.map.inlandWater` | `canal` · `pond` | แหล่งน้ำในอำเภอที่ไม่ติดทะเล — จังหวัดที่มีคลอง/แม่น้ำผ่านเมืองชัด (ตาม research) ใช้ `canal` |
| `province.map.roadLayout` | `grid` `no-east` `no-west` `no-east-west` `no-south` `seeded` | โครงถนนหลัก — `seeded` ให้แต่ละเขตต่างกันแบบสุ่มคงที่ |
| `district.map.archetype` | `urban` · `town` · `rural` | ความหนาแน่น (§3) — ต้องอธิบายเหตุผลใน card |
| `district.map.coastal` | `true`/`false` | **เขต/อำเภอนั้นติดทะเลจริงไหม** (ตัดสินระดับอำเภอ ไม่ใช่ทั้งจังหวัด) |
| `district.map.wat` | `thai` · `lanna` · `chinese` | แบบวัด/ศาลเจ้าหลัก — `lanna` ใช้ได้เฉพาะภาคเหนือ; ภาคเหนือต้องเป็น `lanna` หรือ `chinese` |
| `district.map.landmark` | `{ name, roof, sign }` | สถานที่ประจำเขต (ชื่อเป็นประเภทกลาง ๆ หรือชื่อจริงที่ผ่าน research) — **ห้ามใช้ "อนุสาวรีย์ประจำเมือง" กับเขตใหม่** |
| `district.map.roof` / `houseRoof` | hex (ไม่บังคับ) | สีหลังคาเฉพาะถิ่น เมื่อ research บอกว่าต่างจากภาคชัดเจน |
- `rent`/`salary` เป็นตัวคูณที่ต้องมีแหล่ง ([economy.md](economy.md)); test บังคับช่วง: จังหวัด 0.4–1.5 · ย่าน ค่าเช่า 0.4–2.5 เงินเดือน 0.5–2.0
- `zone` ของย่านในกรุงเทพฯ ต้องชี้โซนที่มีอยู่จริงใน `src/world/districts.ts`
- `mapId` ใช้เมื่อย่านนั้นมีแผนที่เฉพาะ (district scene)

## 2. สูตรเพิ่มพื้นที่ใหม่ (ทำตามลำดับ ห้ามข้าม)
### 2.1 เพิ่มจังหวัด
1. **Research:** สร้าง `docs/research/<province-id>.md` ตาม template และใส่บรรทัด `> geo: <province-id>` ใต้หัวเรื่อง — ต้องตอบ: ภาค, ติดทะเล/แม่น้ำ/คลองไหม, ความหนาแน่นของแต่ละอำเภอ, landmark, วัด/ศาสนสถานหลัก, ค่าแรง/ค่าเช่า (มีแหล่ง), อาหาร/อาชีพ/ประเพณี, visual brief (สีหลังคา วัสดุ ต้นไม้)
2. **Research ระดับอำเภอ:** อย่างน้อย 3–4 อำเภอ แต่ละอำเภอมี card ของตัวเอง หรือหัวข้อใน card จังหวัด พร้อมบรรทัด `> geo: <province-id>/<district-id>`
3. **ข้อมูล:** เพิ่มจังหวัดใน `src/data/geo.json` พร้อม `map` ครบทุกช่อง และทุกอำเภอมี `map` ครบ (อำเภอละ 2–3 ย่าน)
4. **เมนู:** เพิ่มชื่อเดียวกันใน `src/data/provinces.json` ลำดับเดียวกับ `geo.json`
5. **ภาค/สีใหม่ (ถ้าจำเป็น):** ถ้าภาคยังไม่มีใน palette ต้องถามเจ้าของก่อน แล้วเพิ่มใน `PALETTES` (`src/world/city-maps.ts`) + type ใน `geo.ts` + รายการค่าที่ยอมรับใน `geo-config.test.ts`
6. **เนื้อหา:** event/กิจกรรมเฉพาะจังหวัดอย่างน้อย 3 อัน ที่อิง card (ดู [event-flow.md](event-flow.md))
7. **ตรวจ:** `npm run check` ผ่าน → เปิด `test-results/screens/desktop/10-map-<province-id>.png` และเข้าแผนที่ทุกอำเภอด้วย `__ol.enterMap(ชื่อจังหวัด, district-id, hood-id)` ทั้งกลางวันและกลางคืน เทียบกับ visual brief
8. **ย้ายถิ่น:** ทดสอบไป-กลับจังหวัดนี้ผ่านสถานีขนส่ง และค่าเช่า/เงินเดือนเปลี่ยนถูก
9. อัปเดตตารางสถานะใน `docs/research/README.md`

### 2.2 เพิ่มเขต/อำเภอในจังหวัดเดิม
1. research card หรือหัวข้อใหม่ พร้อม `> geo: <province-id>/<district-id>`
2. เพิ่มใน `geo.json` พร้อม `map` ครบ (archetype, coastal, wat, landmark)
3. `npm run check` + ดูภาพทุกย่านของอำเภอนี้
4. ถ้าเขตนั้นสำคัญพอ → ทำแผนที่เฉพาะ (district scene, §5)

### 2.3 เพิ่มย่าน
- เพิ่มใน `geo.json` พร้อม `vibe` จาก research, `rent`/`salary` ที่อ้างอิงได้, `tags` ที่ใช้กับ event
- ไม่ต้องเขียน test เพิ่ม — `maps.test.ts` วนทุกย่านอัตโนมัติ

### 2.4 สิ่งที่ test จับให้อัตโนมัติ vs สิ่งที่ต้องตรวจเอง
| test จับได้ | ต้องตรวจเอง (คนหรือ AI ผู้ตรวจ) |
|---|---|
| ขาด `map` / ค่าไม่ถูกชนิด / ภาคกับวัดขัดกัน | ค่าที่เลือก**ตรงกับความจริง**ไหม (ติดทะเลจริง? หนาแน่นจริง?) |
| ไม่มี research card ที่ประกาศ `geo:` | เนื้อหาใน card ถูกต้องและมีแหล่ง 2+ แหล่ง |
| ใช้ landmark กลางกับเขตใหม่ | ชื่อ landmark เหมาะสม ไม่ผิด content-safety |
| ตัวคูณเงินหลุดช่วง | ตัวเลขมีแหล่งอ้างอิงจริง |
| เมนูกับ geo.json ไม่ตรงกัน | ภาพออกมาดูเป็นพื้นที่นั้นจริง (ภาพ e2e) |
| แผนที่ทุกย่าน: โซนผิด ทับกัน เดินไม่ถึง อาคารหลักไม่ครบ | ป้ายชื่อ/ข้อความภาษาไทยถูกต้อง |

## 3. แผนที่เมืองแบบสร้างอัตโนมัติ (`src/world/city-maps.ts`)
- ทุก จังหวัด+เขต+ย่าน ได้แผนที่ของตัวเองจาก **seed = hash ของ id** — ผลต้องเหมือนเดิมทุกครั้ง (ห้าม `Math.random`)
- ขนาดปัจจุบัน 40×28 tiles (สเกล 16px เดิม); ถนนหลักแถว 9–10, 21–22 และคอลัมน์ 13–14, 27–28 (บางเส้นถูกตัดตามจังหวัด)
- **มาตรฐานใหม่เมื่อย้ายเป็น 32px** ([art.md §2](art.md) — 1 tile ≈ 1 ม.):
  | สิ่งของ | ขนาด (tile) |
  |---|---|
  | แผนที่ย่าน | ค่าเริ่มต้น 96×64, ใหญ่สุด 128×96 (ใหญ่กว่า 8 ล้านพิกเซลต่อเลเยอร์ต้องแบ่ง chunk) |
  | ถนนหลัก 2 ช่องจราจร | 6–7 (ช่องละ 3) |
  | ถนนสายรอง / ซอย | 3–4 |
  | ทางเท้า | 2 (ย่านแน่น 1–2) |
  | ตึกแถว 1 คูหา | กว้าง 4, ลึก 6–8 |
  | บ้านเดี่ยว | 8–12 × 6–8 + รั้ว/ลาน |
  | อาคารพาณิชย์/ออฟฟิศ | 12–20 กว้าง |
  | ลานวัด | 16–30 ด้าน |
  - generator ต้องรับขนาดจากค่าคงที่ ไม่ hardcode พิกัดถนน (คำนวณจากโครงผังของ archetype)
  - ภาพรวมเมือง (zoom out) ใช้เลเยอร์แผนที่เรียบ 8 px/tile แยกต่างหาก
- ทุกแผนที่ต้องมี hotspot หลักครบ: บ้าน · ออฟฟิศ · ร้านสะดวกซื้อ · ตลาด · โรงพยาบาล · ร้านตัดผม · ร้านเสื้อผ้า · ยิม · สถานีขนส่ง · ร้านอาหาร · วัด/ศาลเจ้า · landmark · สวนหรือหาด
- **archetype** (`district.map.archetype` → `spec.style.archetype`) — กำหนดความหนาแน่นและหน้าตา:
  | archetype | ใช้กับ | ลักษณะ |
  |---|---|---|
  | `urban` | เขตชั้นในกรุงเทพฯ, เมืองใหญ่ (เช่น หาดใหญ่) | ตึกแถวเรียงหน้าถนน พื้นคอนกรีต ต้นไม้น้อย ร้านค้า/มอเตอร์ไซค์/สายไฟเยอะ |
  | `town` | อำเภอเมือง, ปริมณฑล | ตึกแถวริมถนนหลัก + บ้านเดี่ยว ผสมพื้นหญ้า |
  | `rural` | อำเภอรอบนอก | บ้านเดี่ยว/บ้านไม้ยกใต้ถุน (เหนือ/อีสาน) หญ้า ทุ่ง ทางดิน ต้นไม้มาก |
- การจัด archetype ของแต่ละเขตเป็น**การประมาณของเกม** ต้องบันทึกใน card และควรอิงความหนาแน่นประชากรจริงเมื่อมีข้อมูล
- landmark ประจำเขตใช้ประเภทกลาง ๆ (หอคอย ห้าง ศาลเจ้า ท่าเรือ สถานีรถไฟ อนุสาวรีย์) — ใช้ชื่อสถานที่จริงได้ถ้ามี research และไม่ผิด [content-safety.md §3](content-safety.md)
- วัด: `thai` (ภาคกลาง), `lanna` (ภาคเหนือ), `chinese` (ย่านจีน) — เลือกตามพื้นที่จริง

## 4. กฎโซนและการวาง object (ใช้กับทุกแผนที่)
- **จุดฐาน (base) ของ object เป็นตัวตัดสินโซน** ไม่ใช่ยอด — ยอดต้นไม้/ป้าย/เสาไฟยื่นขึ้นเหนือฐาน (ทิศเหนือ) ได้ตามมุมมอง 2.5D
- โซนตัดสินด้วย `districtZone(spec, tx, ty)` — ใช้ตัวเดียวกันทั้ง art, collision และ audit
- ลำดับความสำคัญ: น้ำ > ถนน > ทางเท้า > ทราย > ป่าชายเลน > อาคาร > `green` (tile ทางเท้าที่ตัดกับถนนถือเป็นถนน)

### ตารางอนุญาต
| Object | โซนที่วางได้ |
|---|---|
| ต้นไม้, พุ่มไม้ | `green` (หรือ `mangrove` สำหรับป่าชายเลน) — ต้องเป็น tile จำนวนเต็มและ `grid=1` |
| อาคาร, บ้าน | `green` เท่านั้น ห้ามทับกันเอง ห้ามทับถนน/ทางเท้า/น้ำ |
| แผงลอย / รถเข็น (`stall`, `cart`) | `sidewalk`, `green` — **ห้ามบนถนน** |
| เสาไฟ/เสาไฟฟ้า (`lamp`, `power`) | `sidewalk` (หรือ `green`) |
| ม้านั่ง, ถังขยะ, ป้าย, มอเตอร์ไซค์จอด, จุดวิน | `sidewalk` (ม้านั่ง/ถังขยะในสวนได้) |
| ศาลพระภูมิ (`spirit`) | `green` หน้าบ้าน/อาคาร ห้ามบนทางเท้า/ถนน |
| ฝาท่อ, ตะแกรงระบายน้ำ, แอ่งน้ำ | `road` |
| เรือ, ทุ่น | `water` |
| ของชายหาด (อวน, ปู, มะพร้าว) | `sand` |
| hotspot | tile ที่เดินได้ (`grid === 0`) ไม่อยู่ในน้ำ/อาคาร/ขอบ |

### กฎเหล็ก
1. ห้ามวางฐาน object ทับ อาคาร บ้าน ถนน ทางเท้า น้ำ ทราย หรือทับกันเอง (ยกเว้นที่ตารางอนุญาต)
2. ห้ามวางต้นไม้ชิดผนังอาคาร (ทรงพุ่มกว้าง ~0.625 tile ต้องไม่ทับตัวอาคาร)
3. ต้นไม้/ป่าชายเลนที่บล็อกการเดินต้อง mark `grid = 1`; น้ำต้องบล็อกทุก tile ยกเว้นสะพาน/ท่าเรือ
4. ประตูอาคารต้องเดินไปถึงได้ และ tile หน้าประตูห้ามมีบ้าน/ต้นไม้ขวาง
5. ห้ามสุ่มตำแหน่งแบบ runtime — ใช้ตำแหน่งที่กำหนดหรือ seeded RNG
6. สะพาน ทางม้าลาย เส้นหยุด ต้องคำนวณจากจุดตัดจริงของถนน/น้ำในแผนที่นั้น **ห้าม hardcode ตำแหน่งของแผนที่อื่น**
7. ขนาดแผนที่ต้องอ่านจาก `spec.w/h` ห้าม hardcode 40×28 ในโค้ดที่ใช้ร่วมกัน
8. prop ประเภทใหม่: เพิ่มใน `PROP_ZONES` (`src/world/map-audit.ts`) + วาดในโมดูล art + เพิ่มในตารางนี้

## 5. แผนที่เฉพาะเขต (District scene)
- ใช้กับเขตที่มี research ลึกและต้องการผังเฉพาะ (ตัวอย่าง: บางขุนเทียน 48×32 ใน `src/world/district-maps.ts`)
- ข้อมูล: `DistrictSpec` (`grid`, `buildings/houses`, `roads/sidewalks`, `water/sand/mangroveZones`, `trees/mangroves/props/hotspots`, `spawn`, `palette`, `zoneRects`)
- ผังควรสะท้อนภูมิศาสตร์จริงตาม card (ทิศของทะเล/คลอง/ถนนหลัก) แม้จะย่อส่วน
- กิจกรรมในแผนที่เฉพาะต้องอิงอาชีพ/สถานที่จริงของเขต (บางขุนเทียนมี 12 จุด: ตลาด ศาลเจ้า ท่าเรือ หาด ป่าชายเลน บ่อกุ้ง โรงงาน ห้องเย็น โกดัง ร้านอาหารทะเล อนามัย โรงเรียน)
- ต้องมีทางเข้า-ออก (hotspot) กลับแผนที่เมืองเสมอ และบันทึก `life.activeDistrict` ในเซฟ

## 6. แผนที่เมืองเก่า 40×28 (scene `city`, legacy)
- ใช้ `BUILDINGS/HOUSES/TREES/...` ใน `src/world/world-data.ts`/`game.ts` และ `tileZone()` + `auditLayout()`
- โซน: ถนนแนวนอนแถว 8–9, 20–21 · ถนนแนวตั้งคอลัมน์ 12–13, 30–31 · ทางเท้าแถว 7, 10, 19, 22 และคอลัมน์ 11, 14, 29, 32 · สระน้ำ x 6–7, y 24–25 · สวน x 3–9, y 23–26
- object ที่เพิ่ม/ย้ายในฉากนี้ต้องเพิ่มลง `auditLayout()` พร้อมโซนที่อนุญาต
- ตำแหน่ง object อยู่ในส่วน `WORLD DATA`: `BUILDINGS`, `HOUSES`, `TREES`, `BUSHES`, `SCOOTERS`, `LIGHTS` — อาคาร/บ้านแก้ที่ data เดียว แล้ว hotspot และ collision จะตามเอง
- static prop เป็นภาพอย่างเดียว (ไม่บล็อกการเดิน) เว้นแต่ตั้งใจใส่ใน `cityGrid`; ของที่ต้องบล็อกให้แก้ `cityGrid`/`officeGrid`/`homeGrid` พร้อมกัน
- ย้ายอาคาร/บ้านแล้วต้องตรวจว่า door hotspot ยังเดินไปถึงได้
- รายละเอียดตลาดกลางคืนเยาวราช: `YAOWARAT_STALLS/TABLES/LOCALS/NEON/CLUTTER` ใน `game.ts` — เพิ่ม/ย้ายแล้วต้องลง `auditLayout()` (โซน sidewalk); แสงวาดใน `drawLighting()` หลัง tint; `drawYaowaratDynamic()` วาดเฉพาะเมื่อกล้องเห็นเขต (`yaowaratInView`)
- งานใหม่ควรทำบนระบบ spec (§3, §5) แทนฉากนี้
