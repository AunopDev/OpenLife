# กฎการทำงาน (Workflow) — สำหรับคนและ AI ทุกตัว

## 1. ก่อนเริ่มงาน
1. อ่าน [`AGENTS.md`](../../AGENTS.md) ทั้งไฟล์ และไฟล์หมวดใน `docs/rules/` ที่งานแตะ
2. อ่าน section ที่เกี่ยวข้องใน [`docs/GDD.md`](../GDD.md) และ research card ใน `docs/research/`
3. ดูโค้ดจริงก่อนเชื่อเอกสาร — ถ้าเอกสารกับโค้ดไม่ตรงกัน ให้แจ้งผู้ใช้ และอย่าเดาเองว่าฝั่งไหนถูก
4. ตอบให้ได้ 4 ข้อนี้ก่อนลงมือ:
   - ผู้ใช้ต้องการผลลัพธ์อะไร (ไม่ใช่แค่ "ทำอะไร")
   - แตะระบบ/ไฟล์ไหน และกระทบเซฟเก่าไหม
   - ต้องรีเสิร์ชอะไร (ดู [research.md](research.md))
   - จะตรวจอย่างไรว่าเสร็จจริง

## 2. เมื่อไรต้องถามเจ้าของโปรเจ็คก่อน
- เพิ่ม library / framework / บริการภายนอก / backend
- เปลี่ยน design pillar, ความยากโดยรวม, จำนวนบท, ระบบเวลา, ระบบตอนจบ
- เพิ่มเนื้อหาที่อยู่ในเขตเทาของ [content-safety.md](content-safety.md)
- ลบระบบ/เนื้อหาที่มีอยู่, เปลี่ยน save format แบบเซฟเก่าเล่นต่อไม่ได้
- refactor ใหญ่ที่เกิน 1 โมดูล หรือเปลี่ยนโครงโฟลเดอร์
- งานที่ระบุไม่ชัดและมีทางเลือกที่ผลต่างกันมาก

**ไม่ต้องถาม:** แก้บั๊กที่ชัดเจน, เติม research card, เพิ่ม event ที่ผ่านกฎทั้งหมด, ปรับภาพตามกฎ art

## 3. ระหว่างทำ
- แก้แบบ surgical — เปลี่ยนเท่าที่จำเป็น ไม่จัดรูปแบบไฟล์ทั้งไฟล์ ไม่ rename โดยไม่มีเหตุผล
- รักษาพฤติกรรมเดิมไว้ ยกเว้นงานนั้นสั่งให้เปลี่ยน (เช่น การเดิน/collision/hotspot)
- ทุกตัวเลขที่อิงโลกจริงต้องมีแหล่งอ้างอิง หรือติดป้าย `TODO(research)` / "สมมติ"
- เจอบั๊กนอกขอบเขตงาน → จดไว้แล้วรายงาน ไม่แก้เงียบ ๆ (ยกเว้นบั๊กเล็กมากที่ขวางงานอยู่)

## 4. Definition of Done (ต้องครบทุกข้อ)
- [ ] **`npm run check` ผ่านทั้งหมด** — typecheck, unit test, build, e2e (console error + audit ทั้งหมด + เซฟ + ทุกแผนที่ บน 4 ขนาดจอ) — รายละเอียด [quality.md](quality.md)
- [ ] เพิ่ม test สำหรับสิ่งที่เพิ่มใหม่ตาม [quality.md §3](quality.md)
- [ ] งานใหญ่/งานเสี่ยงผ่านผู้ตรวจคนที่สองตาม [quality.md §5](quality.md)
- [ ] บั๊กที่เจอแต่ไม่ได้แก้ จดใน `docs/BUGS.md`
- [ ] ดูภาพจริงของฉากที่แตะ ทั้ง **มือถือ portrait, มือถือ landscape และเดสก์ท็อป** และทั้ง **กลางวันและกลางคืน** ถ้าเป็นงานภาพ
- [ ] เซฟเก่ายังโหลดได้ (หรือมี migration แล้วตาม [code.md §4](code.md))
- [ ] research card อัปเดตแล้ว (ถ้าแตะโลกจริง)
- [ ] `docs/GDD.md` อัปเดตแล้ว ถ้าเปลี่ยน mechanic หรือตัวเลข
- [ ] ข้อความผู้เล่นเป็นภาษาไทยที่ผ่าน [story-flow.md §5](story-flow.md)
- [ ] ไม่มี `Math.random` ใหม่ในงานภาพ/แอนิเมชัน/การสร้างแผนที่ (ใช้ seeded RNG)
- [ ] วัตถุ/ตัวละครที่เพิ่มมีแอนิเมชันและเสียงตาม [animation.md](animation.md) / [audio.md](audio.md) (หรือจดเป็นงานค้างไว้)
- [ ] asset ใหม่มีที่มา/สิทธิ์ใช้ และอยู่ในงบขนาด ([assets.md](assets.md))

## 5. การรายงานผลให้ผู้ใช้
- ตอบเป็น **ภาษาไทย** เสมอ (ศัพท์เทคนิค/ชื่อไฟล์/โค้ดใช้อังกฤษได้)
- ประโยคแรกบอกผลลัพธ์ ว่าเสร็จหรือไม่เสร็จ
- บอกสิ่งที่**ยังไม่ได้ทำ/ยังไม่ได้ตรวจ**ตรง ๆ ห้ามบอกว่าผ่านถ้าไม่ได้รันจริง
- อ้างไฟล์เป็นลิงก์ `path:line`
- อย่าใช้ศัพท์ที่ตัวเองตั้งขึ้นระหว่างทำงานโดยไม่อธิบาย

## 6. Git / การเผยแพร่
- **ห้าม commit / push / สร้าง PR / deploy เว้นแต่ผู้ใช้สั่งในรอบนั้น** — ตอนนี้เจ้าของจัดการ git และ deploy เอง
- ห้ามลบไฟล์ที่ไม่รู้ว่ามาจากไหน
- `prototype/` เป็น legacy: ห้ามแก้ ยกเว้นย้อนกลับฉุกเฉิน
- `dist/` เป็นผลจาก build ไม่ต้องแก้มือ

## 7. ทำงานพร้อมกันหลาย AI/session
- งานที่แก้ไฟล์ชุดเดียวกัน ห้ามทำพร้อมกัน — แบ่งงานตามไฟล์/โมดูล
- `AGENTS.md` และ `docs/rules/` แก้ได้ทีละ session เท่านั้น
- ก่อนแก้ไฟล์ให้อ่านเวอร์ชันล่าสุดบนดิสก์เสมอ (อาจมี session อื่นแก้ไปแล้ว)
- เขียน handoff ให้คนต่อไปทำต่อได้: ทำอะไรไปแล้ว · เหลืออะไร · ไฟล์ไหน · ตรวจยังไง · ปัญหาที่พบ

## 8. เมื่อไม่แน่ใจ
- เลือกทางที่ **ย้อนกลับได้** และ **กระทบน้อย** ก่อน
- ถามด้วยตัวเลือกที่ชัด พร้อมคำแนะนำของคุณ (ไม่ถามปลายเปิดลอย ๆ)
- ห้ามแต่งข้อเท็จจริง ห้ามบอกว่าทดสอบแล้วถ้ายังไม่ได้ทดสอบ
